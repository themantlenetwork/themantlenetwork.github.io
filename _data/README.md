# Data directory

This directory contains the datasets consumed by the MANTLE NETWORK website, GeoNames reference files used for member geocoding, and working files generated by the Laposta data pipelines.

## Structure

```text
_data/
├── committee_members.csv       # Public scientific committee dataset
├── network_members.csv         # Public member directory dataset
├── theme.yml                   # Theme settings
├── reference/
│   ├── README.md
│   ├── cities1000.txt          # GeoNames city gazetteer
│   └── countryInfo.txt         # GeoNames country reference
└── private/                    # Local working data; must not be committed
    ├── committee/
    │   ├── laposta_snapshot.json
    │   ├── committee_review.csv
    │   └── committee_keywords.csv
    ├── network/
    │   ├── laposta_snapshot.json
    │   ├── network_review.csv
    │   └── network_keywords.csv
    └── newsletter/
        ├── laposta_snapshot.json
        └── subscribers.csv
```

## Datasets and outputs

| Pipeline | Input | Website output | Private output |
|---|---|---|---|
| Scientific committee | Laposta scientific committee list | `committee_members.csv` | Raw snapshot, review report and keyword inventory |
| Member directory | Laposta member directory list | `network_members.csv` | Raw snapshot, review report and keyword inventory |
| Newsletter | Laposta newsletter list | None | Raw snapshot and subscriber CSV |

The two public CSV files are read by Jekyll through `site.data.committee_members` and `site.data.network_members`. Newsletter subscriber data is not used by the public website.

## Processing scripts

Scripts and launchers are in the repository-root `scripts/` directory:

- `geocode_members.py`: shared pipeline for committee and member-directory data. It retrieves Laposta members or accepts JSON, CSV and Excel input; standardises names, countries and research keywords; matches city/country information against GeoNames; and writes a Jekyll-ready public CSV plus private review and keyword reports.
- `update_committee_members.sh`: retrieves the active scientific committee list and runs the shared processing pipeline.
- `update_network_members.sh`: retrieves the active member-directory list and runs the same pipeline.
- `newsletter_subscribers.py`: retrieves newsletter subscribers from Laposta and writes a JSON snapshot and flattened CSV. It does not geocode or generate public website data.
- `update_newsletter_subscribers.sh`: local launcher for the newsletter export.

Run from the repository root:

```bash
bash scripts/update_committee_members.sh
bash scripts/update_network_members.sh
bash scripts/update_newsletter_subscribers.sh
```

## Reference data

`reference/cities1000.txt` and `reference/countryInfo.txt` are GeoNames reference files required by `geocode_members.py`.

- The committee GitHub Actions workflow downloads both files at runtime into `_data/reference/`.
- The member-directory workflow expects both files to already exist in `_data/reference/`.
- For local committee or directory processing, ensure both files are present.

See [reference/README.md](reference/README.md) for the reference-file note.

## Automated workflows

The three workflows in `.github/workflows/` can be run manually and are also scheduled weekly (Mondays, UTC):

| Workflow | Schedule (UTC) | Behaviour |
|---|---:|---|
| `update-committee.yml` | 06:15 | Builds committee CSV, uploads private committee files as an artifact, and commits/pushes the public CSV only when it changes |
| `update-directory.yml` | 06:30 | Builds directory CSV, uploads private network files as an artifact, and commits/pushes the public CSV only when it changes |
| `update-newsletter.yml` | 06:45 | Exports newsletter data and uploads it as an artifact; does not commit or push |

All three use the repository secret `LAPOSTA_API_KEY`. Private artifacts are uploaded as directories using `actions/upload-artifact@v4` and retained for 14 days. GitHub Actions creates the downloadable ZIP; do not ZIP the files manually beforehand.

## Credentials and privacy

For local use, place the Laposta API key in a root-level `.env` file:

```dotenv
LAPOSTA_API_KEY=your_api_key
```

The launchers load this file automatically. In GitHub Actions, configure the same value as a repository Actions secret named `LAPOSTA_API_KEY`.

**Never commit `.env`, raw Laposta snapshots, subscriber exports, or review reports.** The repository's `.gitignore` should exclude `_data/private/` and `.env`. The private folder in the structure above describes local/runtime outputs; its contents are not website data.

## Python requirements

Install the dependencies from the repository root:

```bash
python -m pip install -r requirements.txt
```

The scripts use Python 3.12 in GitHub Actions. `requests` is required for the Laposta API. `openpyxl` is only needed when reading Excel input with `geocode_members.py`.
